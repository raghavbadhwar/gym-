## 2024-04-24 - SQLAlchemy Enum Group By Optimization
**Learning:** When refactoring SQLAlchemy queries to use `.group_by()` on Enum columns, letting SQLAlchemy natively map the Enum object as a dictionary key is cleaner and safer than manually parsing `.name` or `.value`. Additionally, retaining a separate `total = self.db.query(Member).count()` query ensures that members with missing or unmapped states are accurately included in the total, rather than simply summing the `group_by` results.
**Action:** When replacing individual `.count()` queries with a single `.group_by()`, always check if a total count is also needed and keep it as a separate `.count()` query to handle `NULL` or unmapped values. Use the native Enum mapping for lookup keys (e.g., `state_counts.get(MemberState.ACTIVE, 0)`).
