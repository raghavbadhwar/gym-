## 2026-04-21 - Optimize get_stats using Enum grouping in SQLAlchemy
**Learning:** When refactoring SQLAlchemy queries to use `.group_by()` on Enum columns, you should let SQLAlchemy handle Enum mapping natively. When creating a dictionary from the result, you can map the raw state object directly as the dictionary key (e.g., `{state: count}`) and look up using the Enum instance (e.g., `stats.get(MemberState.ACTIVE, 0)`). Avoiding manual parsing of `.name`, `.value`, or `str()` prevents `KeyError` exceptions or fragile key matching. Additionally, keeping a separate `.count()` query for the overall total ensures members with missing or unmapped states are accurately included.
**Action:** Next time I optimize multiple `.count()` queries on an Enum column, I will use a single `.group_by()` query and rely on SQLAlchemy's native Enum instance mapping for dictionary lookup, while preserving a distinct total query if needed to capture NULL or default states.
