## 2024-05-15 - [SQLAlchemy Query Optimization with Enums]
**Learning:** When optimizing multiple `.count()` queries by refactoring to a single `.group_by()` query on an Enum column, SQLAlchemy handles Enum mapping natively. We can map the raw state object directly as the dictionary key (e.g., `{state: count}`) and look it up using the Enum instance (e.g., `.get(MemberState.ACTIVE, 0)`). Manually parsing `.name`, `.value`, or `str()` can cause KeyErrors or fragile key matching. Additionally, keeping a separate total count query is crucial so members with missing (NULL) or unmapped states are accurately included in the overall total.
**Action:** When aggregating Enum columns, always use the raw Enum object as the dictionary key. Always maintain a separate query for the total count to correctly handle NULL values rather than summing the grouped results.
