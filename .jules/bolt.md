## 2024-05-18 - [Optimization Scope Constraints]
**Learning:** When acting as Bolt and instructed to implement ONE small performance improvement, strictly limit changes to a single optimization. Bundling multiple improvements, even if conceptually related, violates constraints and will fail code review. Also, when optimizing SQLAlchemy queries that aggregate and count data across rows with Enum columns, the dictionary created from the `group_by` will have keys that are the Python Enum members (e.g., `MemberState.ACTIVE`), not strings, and `sum(counts.values())` must be used to ensure total logic includes all rows, including those with NULL values.
**Action:** When asked for ONE improvement, identify multiple opportunities but selectively implement only the highest impact one, and revert any experimental secondary optimizations before final review.
