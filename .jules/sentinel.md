## 2024-05-24 - Webhook Authentication Bypass and Timing Attacks
**Vulnerability:** The WhatsApp webhook endpoint lacked signature verification (`X-Hub-Signature-256`), meaning anyone could spoof requests and trigger webhook logic. Additionally, the verification endpoint used a standard equality check `==` for the token, which is susceptible to timing attacks. Finally, FastAPI's error handler was swallowing `HTTPException`s into 200 OK responses, violating fail-secure principles.
**Learning:** In FastAPI, when reading the raw request body (e.g., `await request.body()` for HMAC-SHA256 signature verification), the framework automatically caches the body in memory. This ensures subsequent reads like `await request.json()` in the route handler still function correctly. Explicitly catching `HTTPException` before general `Exception` handlers is critical to ensure fail-secure error codes (401/500) are returned instead of being swallowed.
**Prevention:** Always implement signature verification on webhook endpoints using `hmac.compare_digest` or `secrets.compare_digest` to prevent timing attacks. Enforce a fail-secure strategy by raising an HTTP 500 error if the app secret is missing, and an HTTP 401 error if the signature is invalid. Ensure `HTTPException` is explicitly handled to propagate error codes correctly.
