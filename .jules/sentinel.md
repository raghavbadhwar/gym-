## 2024-05-15 - Missing Webhook Signature Validation and Timing Attack Vulnerability
**Vulnerability:** The WhatsApp webhook endpoint (`/whatsapp` POST) in `app/routers/webhooks.py` lacked `X-Hub-Signature-256` validation. This allowed any external party to forge requests and impersonate Meta by sending arbitrary payloads, leading to potential data manipulation and unauthorized message sending. Furthermore, standard string equality `==` was used for `hub_verify_token` checking in the GET `/whatsapp` endpoint, creating a potential timing attack vector.
**Learning:** This issue existed because the signature verification logic was omitted during initial webhook implementation, likely due to oversight or prioritizing functionality over security. It is critical to validate the authenticity of incoming webhooks to prevent spoofing. A key technical learning is that FastAPI/Starlette automatically caches the raw request body when reading `await request.body()` for signature verification, meaning subsequent reads like `await request.json()` in the route handler still function correctly and do not throw "stream consumed" errors.
**Prevention:** Always implement signature validation for external webhooks. Ensure that the required secrets (e.g., `whatsapp_app_secret`) are present and enforce a "Fail Secure" strategy by raising a critical error (HTTP 500) if the secret is missing rather than bypassing validation. For all secret comparisons (tokens, hashes, signatures), strictly use `hmac.compare_digest` or `secrets.compare_digest` to mitigate timing attack vulnerabilities.
