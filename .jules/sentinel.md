## 2024-04-11 - Webhook Signature Validation & Exception Handling
**Vulnerability:** The WhatsApp webhook endpoint (`/api/v1/webhooks/whatsapp` POST) in `app/routers/webhooks.py` was processing incoming messages without validating the `X-Hub-Signature-256` signature, and the global catch-all exception handler was swallowing explicit HTTP errors (returning 200 OK), potentially leading to security bypasses.
**Learning:** In FastAPI, catch-all `Exception` blocks will swallow explicitly raised `HTTPException`s if they are not specifically handled or re-raised. This can inadvertently turn security failure statuses (like 401 Unauthorized) into a generic success or 200 OK, especially when designing webhooks to avoid retries by third parties.
**Prevention:** Always place a specific `except HTTPException:` block before a broad `except Exception:` block to ensure intended failure responses are propagated. Ensure webhooks compute expected signatures (e.g., using HMAC-SHA256) and use `hmac.compare_digest` to prevent timing attacks. Provide a fallback validation bypass for unconfigured environments to ensure backward compatibility and prevent breaking changes.
