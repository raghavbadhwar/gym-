## 2024-03-24 - Missing Webhook Signature Validation
**Vulnerability:** The WhatsApp webhook endpoint (`/whatsapp` POST) in `app/routers/webhooks.py` was missing signature validation (`X-Hub-Signature-256`). This allowed unauthenticated requests to spoof Meta webhook events and inject messages, potentially resulting in malicious message processing and billing manipulation.
**Learning:** In FastAPI/Starlette, webhook request bodies can be read using `await request.body()` without consuming the stream permanently, as the framework automatically caches the body in memory. This allows HMAC signature verification to be performed before parsing JSON with `await request.json()`. Additionally, we must employ a 'Fail Secure' strategy by raising an HTTP 500 if the secret (`whatsapp_app_secret`) is misconfigured or missing, rather than bypassing authentication. We must also explicitly catch and re-raise `HTTPException` so intentional 401/500 errors aren't caught by general `except Exception` blocks and swallowed as 200 OKs. Finally, secret comparison must be done using `hmac.compare_digest` to prevent timing attacks.
**Prevention:** Always implement signature verification on incoming webhooks using `hmac.compare_digest`. Ensure webhook endpoint secrets are required, employing a 'Fail Secure' strategy if they are missing. In FastAPI, ensure `HTTPException` is explicitly re-raised when using general catch-all exception blocks in webhook endpoints that return 200 OK by default.
