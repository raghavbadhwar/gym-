## 2024-04-13 - Prevent Swallowing Security Exceptions in Webhooks
**Vulnerability:** The WhatsApp webhook endpoint (`/api/v1/webhooks/whatsapp`) caught all exceptions generically (`except Exception as e:`) and returned an HTTP 200 OK status to prevent Meta from retrying. This caused a fail-open scenario where unauthorized requests (e.g., from failed signature validation raising an `HTTPException(401)`) were swallowed and implicitly treated as successful at the HTTP level.
**Learning:** Broad exception handlers in public webhook endpoints can inadvertently mask security validation failures, leading to false positives in API gateways and preventing proper failure signaling to the client.
**Prevention:** Always explicitly catch and re-raise `HTTPException` (or similar framework-level auth exceptions) before falling back to generic `except Exception` blocks, ensuring that security-related HTTP status codes (like 401 Unauthorized) are properly bubbled up to the client while still handling general runtime errors gracefully.
