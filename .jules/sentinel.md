## 2026-03-13 - [Sentinel: Added Webhook HMAC-SHA256 Signature Validation and Timing Attack Prevention]
**Vulnerability:** Missing signature validation on WhatsApp Webhook endpoint (`POST /api/v1/webhooks/whatsapp`) and timing attack susceptibility on the verify endpoint (`GET /api/v1/webhooks/whatsapp`). The lack of payload verification allowed forged requests mimicking Meta payloads, enabling an attacker to trigger unintended application behavior (e.g. sending malicious messages/escalations) by bypassing authentication.
**Learning:** Security configurations need strict "Fail Secure" policies. Without `X-Hub-Signature-256` validation, webhooks from Meta were implicitly trusted. It's critical to ensure missing or invalid secrets in production actively block execution (HTTP 500) rather than failing open or insecurely. Also, string equality for comparing hashes leaves the system open to timing attacks, necessitating the use of `hmac.compare_digest()` or `secrets.compare_digest()`.
**Prevention:** Always implement webhook signature validation (like HMAC-SHA256) for public-facing callback endpoints. Use `compare_digest` functions to prevent timing attacks. Mandate fail-secure defaults in application configuration parsing where critical secrets are uninitialized.
