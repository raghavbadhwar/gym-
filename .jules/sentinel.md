## 2024-05-24 - Fail-Secure Webhook Signature Verification
**Vulnerability:** The WhatsApp webhook endpoint (`/whatsapp` POST) in `app/routers/webhooks.py` was previously accepting messages without validating the `X-Hub-Signature-256` payload signature from Meta. This meant anyone could spoof webhook payloads to the API.
**Learning:** We need to verify HMAC-SHA256 signatures securely using `secrets.compare_digest` to prevent timing attacks. In addition, when implementing security checks like checking if an app secret is configured, we must adopt a "Fail Secure" strategy. If the `whatsapp_app_secret` is missing from the environment, the app must raise a 500 server error rather than bypassing the check or degrading gracefully. Furthermore, any HTTP Exceptions (like 401 or 500) raised during these checks must be explicitly caught and re-raised before general Exception handlers (which often return generic 200 OKs to prevent Meta from retrying) so that the correct fail-secure error codes are returned to the client.
**Prevention:** Always mandate webhook signature validation for third-party integrations using constant-time comparison functions. When configuration for these security checks is missing, fail securely with a server error. Carefully manage exception handling in FastApi routers to ensure security-related `HTTPException`s bypass general "catch-all" handlers that might swallow the error code.
