## 2025-04-18 - Missing Webhook Signature Verification and Fail-Open Flaw
**Vulnerability:** The WhatsApp webhook endpoint (`POST /whatsapp`) accepted any incoming message payload without verifying the `X-Hub-Signature-256` header, allowing attackers to spoof Meta/WhatsApp requests. Additionally, a broad `except Exception` block silently swallowed specific `HTTPException` raises, returning a `200 OK` status and creating a fail-open condition on errors.
**Learning:** In FastAPI, retrieving the raw request body with `await request.body()` must be done before parsing JSON (`await request.json()`) since parsing alters the raw byte representation, causing signature mismatches. Also, broad exception blocks in webhook handlers will inadvertently suppress intended HTTP error codes (like `401 Unauthorized`) if not properly ordered.
**Prevention:** Always verify incoming webhook signatures using `hmac.compare_digest` with defensive null checks. Explicitly catch and re-raise framework-specific routing exceptions (like `HTTPException`) before generic fallback handlers to ensure errors fail closed.
