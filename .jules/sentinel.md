## 2025-04-24 - Missing Webhook Authentication and Secure Comparison
**Vulnerability:** The WhatsApp webhook endpoints lacked essential security controls. The GET endpoint used standard equality operators (`==`) for token verification (vulnerable to timing attacks), and the POST endpoint failed to validate incoming webhook payloads using the `X-Hub-Signature-256` header (Authentication Bypass), allowing attackers to spoof messages.
**Learning:** Broad exception handlers in FastAPI (e.g., `except Exception:`) can unintentionally swallow security-related `HTTPException` responses (like 401 Unauthorized), converting them to 200 OK responses, creating fail-open security flaws. Additionally, payload signatures must be verified on raw bytes, as JSON parsing alters byte representation.
**Prevention:** Always verify incoming signatures for webhook integrations using constant-time comparison (`hmac.compare_digest`). Extract raw payloads using `await request.body()` for HMAC verification prior to JSON parsing. Explicitly catch and re-raise `HTTPException` before generic exception handlers to prevent fail-open scenarios.
