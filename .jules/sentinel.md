## 2025-03-30 - Fix WhatsApp webhook signature validation and timing attacks
**Vulnerability:** The WhatsApp webhook endpoints (`/api/v1/webhooks/whatsapp` POST and GET) were missing critical signature validation (`X-Hub-Signature-256`) and used insecure string comparison for the `hub.verify_token` check. This allowed anyone to forge webhook payloads, bypass authentication, and bypass webhook verification. The insecure string equality check also exposed the application to timing attacks.
**Learning:** For webhooks handling sensitive user data and interacting with third-party providers like Meta/WhatsApp, signature validation is mandatory to ensure the payload actually came from the trusted provider. Furthermore, using standard equality operators (`==`) for comparing secrets (like verify tokens or signatures) leaks timing information; secure comparison functions like `hmac.compare_digest` or `secrets.compare_digest` must be used.
**Prevention:** Always implement signature validation for webhooks. Require the app secret (`whatsapp_app_secret`) in the server configuration and employ a 'Fail Secure' strategy (e.g., return HTTP 500) if it is missing. Always use `hmac.compare_digest` or `secrets.compare_digest` to compare cryptographic signatures, tokens, and secrets to mitigate timing attacks. Ensure the raw request body is used when calculating the expected signature.
