
## 2026-04-04 - Missing Webhook Signature Validation & Swallowed Exceptions
**Vulnerability:** The WhatsApp webhook endpoint (`/whatsapp` POST) was lacking `X-Hub-Signature-256` validation, allowing any unauthorized entity to send forged webhook payloads to the application. Furthermore, a broad `except Exception as e:` block at the end of the endpoint was catching all exceptions (including `HTTPException`) and returning a `200 OK` status, hiding critical security failures (like `401 Unauthorized` or `500 Internal Server Error`).
**Learning:** Broad exception handling in FastAPI endpoints can inadvertently swallow explicitly raised `HTTPException`s intended for security enforcement, resulting in a false-positive success response to the client. This bypasses the API's 'Fail Secure' strategy.
**Prevention:** Always implement robust signature verification (using `hmac.compare_digest` with constant-time comparison) for external webhook callbacks. When using catch-all exception blocks to prevent client-side retry loops, explicitly catch and re-raise `HTTPException` *before* the general `Exception` handler to ensure intentional HTTP error codes are correctly propagated.
