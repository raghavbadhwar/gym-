## 2026-04-10 - Missing Webhook Signature Validation and Swallowed HTTPException
**Vulnerability:** The WhatsApp webhook POST endpoint lacked signature validation (`X-Hub-Signature-256`), allowing any arbitrary source to spoof messages. Furthermore, when `HTTPException`s were raised during request processing, they were caught by a generic `except Exception:` block and returned as 200 OK responses, creating a fail-open scenario.
**Learning:** Webhook endpoints must always explicitly verify cryptographic signatures provided by the sender. In FastAPI, `HTTPException`s meant to return specific HTTP error codes (like 401 Unauthorized) must be explicitly handled or re-raised before broad exception handlers; otherwise, the intended failure state is swallowed and treated as a success by the client.
**Prevention:** Always implement signature validation for public-facing webhooks using robust string comparison (e.g., `hmac.compare_digest`). Structure error handling in FastAPI routers to explicitly intercept and re-raise `HTTPException` before general `Exception` handlers to maintain fail-secure behavior.
