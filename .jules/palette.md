## 2024-05-24 - Interactive Elements Semantics and Valid Phrasing Content
**Learning:** Found that custom command cards (`.command-card`) were implemented using `div` tags with `onclick` handlers, breaking keyboard accessibility and semantic meaning. Additionally, when converting these to native `button` elements, their inner containers must be converted from `div` to `span` to ensure valid HTML5 phrasing content (since block-level elements like `div` are invalid inside a `button`).
**Action:** Always use native `<button>` elements for interactive command cards. Apply CSS resets (`appearance: none`, `text-align: left`, `width: 100%`) and use `span` for inner structural elements. Explicitly add a `:focus-visible` state using `--border-glow` to ensure proper keyboard navigation visibility.
